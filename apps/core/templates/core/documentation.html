📖 What is mCube?

mCube is a sophisticated algorithmic trading system designed for the Indian stock market. It provides automated trade execution, real-time analytics, risk management, and AI-powered insights to help you make better trading decisions.

The platform integrates with major Indian brokers (Kotak Neo, ICICI Breeze) and supports multiple trading strategies including Futures trading, Nifty Strangles, and Iron Condors.

🚀 Quick Start Guide

Get up and running with mCube in minutes

1

Configure Broker Credentials

Navigate to System Configuration and enter your broker API credentials. mCube supports Kotak Neo (for Options) and ICICI Breeze (for Futures).

2

Authenticate with Brokers

Complete the OTP-based authentication for each broker. This enables secure API access for placing orders and fetching market data.

3

Set Risk Parameters

Configure your risk tolerance, maximum position size, and daily loss limits. This ensures the system respects your risk boundaries.

4

Execute Your First Trade

Go to Trade → Execute Trade and use one of the available algorithms: Futures Algorithm, Nifty Strangle, or Broken Iron Condor.

💡

Pro Tip

Start with paper trading or small positions to familiarize yourself with the system before scaling up.

🧮 Strangle Strike Calculation - Step by Step

Complete formula for arriving at strike prices with a worked example:

📁 apps/strategies/services/strangle_delta_algorithm.py | apps/strategies/shared/strike_calculator.py

Step 1: Base Delta Selection

if days_to_expiry <= 2: base_delta = 0.75% # Higher delta for short expiry else: base_delta = 0.50% # Standard delta

Step 2: Apply All Multipliers (Multiplicative)

adjusted_delta = base_delta × vix_adj × trend_adj × volatility_adj × oi_adj × pcr_adj × news_adj

Step 3: Calculate Strike Distance

strike_distance = spot_price × (adjusted_delta / 100) × days_to_expiry

Step 4: Apply Asymmetric Bias (News + Technical)

call_distance = strike_distance × call_multiplier × news_call_bias × technical_call_adj put_distance = strike_distance × put_multiplier × news_put_bias × technical_put_adj

Step 5: Round to Nearest Strike

call_strike = round((spot + call_distance) / 50) × 50 put_strike = round((spot - put_distance) / 50) × 50

VIX14.5 (range 12.5-14 → 1.5x)

Near ResistanceYes (call_adj=1.08)

🛡️ Broken Iron Condor Strategy

The Broken Iron Condor is a 3-leg strategy that adds downside protection to a regular strangle. Unlike a standard 4-leg Iron Condor, this "broken" version only hedges the put side.

🧮 Iron Condor Strike Calculation - Step by Step

Complete logic for all 3 legs with a worked example:

📁 apps/strategies/strategies/kotak_broken_iron_condor.py | apps/strategies/shared/strike_calculator.py

Step 1: Calculate Strangle Strikes (Legs 1 & 2)

Uses same delta-based algorithm as Strangle strategy:

# Same as Strangle calculation strike_distance = spot × (adjusted_delta / 100) × days_to_expiry call_strike = round((spot + strike_distance) / 100) × 100 put_strike = round((spot - strike_distance) / 100) × 100

Step 2: Get Option Premiums

call_premium = fetch_option_premium(call_strike, 'CE') put_premium = fetch_option_premium(put_strike, 'PE') total_premium = call_premium + put_premium max_profit = total_premium × quantity # (lot_size = 50)

Step 3: Calculate Insurance Strike (Leg 3)

risk_budget = max_profit × risk_multiplier max_loss_per_share = risk_budget / quantity insurance_strike_raw = put_strike - max_loss_per_share insurance_strike = round(insurance_strike_raw / 100) × 100 # Safety floor: must be at least 100 points below put strike if insurance_strike >= put_strike: insurance_strike = put_strike - 100

📊 Broken Iron Condor P&L Profile

Understanding the risk/reward characteristics:

Scenario Outcome Risk Level
Max Profit Net Premium = (CE + PE premium) - Insurance cost Target
Downside Loss Capped at (Put Strike - Insurance Strike) × Qty Defined
Upside Loss Unlimited (managed via stop-loss) Managed
Profit Zone Between Put Breakeven and Call Breakeven Ideal
💡

Why "Broken" Iron Condor?

A standard Iron Condor has 4 legs with hedges on both sides. Our version is "broken" because we only hedge the put side (downside protection), keeping the call side unhedged for higher premium collection. This is ideal when you expect range-bound markets with slightly bullish bias.

🚀 Getting Started

The Telegram bot provides a rich interactive menu for managing trades, monitoring positions, and controlling background tasks - all from your phone.

# Start the bot (only ONE instance at a time) python manage.py run_telegram_bot --force # In Telegram, send: /start # Interactive main menu /positions # Quick jump to positions /core # Quick jump to settings /test # Connectivity check

Security: Only authorized chat IDs (from CredentialStore) can interact with the bot. A file lock (/tmp/mcube_telegram_bot.lock) prevents duplicate instances.

⚙️ Tasks Control

The Tasks sub-menu provides full control over all 20+ background tasks organized by category:

  1. Category Overview — Shows active/total counts per category (Data, Strategies, Transactions, Monitoring, Risk, Reports)
  2. Category Detail — Lists each task with its schedule, toggle (enable/disable) and "Run Now" buttons
  3. Bulk Actions — Start All / Stop All toggles every task at once

Toggling a task updates CeleryTaskState and automatically restarts Celery Beat via ensure_celery_running(). "Run Now" sends the task to Celery with _bypass_guard=True.

⚡ Quick Actions & Safety

Quick actions execute immediately. Dangerous actions (Pause Trading, Close All Positions) require a confirmation step:

Action What it does Confirmation?
Pause Trading Sets isDayTradable=No in NseFlag Yes
Resume Trading Sets isDayTradable=Yes in NseFlag No
Close All Positions Triggers close-trading-day task Yes
Refresh Breeze Triggers refresh-breeze-session task No
Run Futures Algo Triggers execute-futures-algorithm task No
Force Data Sync Triggers morning-data-sync task No

🏗️ Architecture (Mixin Pattern)

The bot is split into three files using Python mixins for clean separation of concerns:

File Class Responsibility
telegram_bot.py TelegramBotHandler Main class, callback router, position/trade handlers, OTP relay
telegram_bot_menus.py MenuMixin All menu rendering, button layouts, callback handler methods
telegram_bot_data.py DataMixin All @sync_to_async data fetchers (DB queries, system checks)

MRO: TelegramBotHandler(MenuMixin, DataMixin) — all methods accessible on self.

Callback Routing: Prefix-based dispatch in _route_callback(). Key prefixes: menu_, task_cat_, tt_ (toggle), tr_ (run), qa_ (quick action), broker_, core_, confirm_.

Thread Safety: All data fetchers use @sync_to_async(thread_sensitive=False) with close_old_connections() before every DB access.

🔑 OTP Relay (Breeze Auto-Login)

When the Breeze auto-login process needs an OTP, it sets breeze_otp_request=pending in NseFlag. The bot watches for 4-6 digit plain text messages and stores the OTP via NseFlag cross-process communication.

🔄 Task Lifecycle

  1. Definition: All tasks defined in TASK_DEFAULT_CONFIG (apps/core/task_config.py) with schedule defaults
  2. State: CeleryTaskState model tracks enabled/disabled + optional custom schedules per task
  3. Loading: load_beat_schedule() in celery.py reads DB state, applies custom schedules via _build_custom_schedule()
  4. Runtime Guard: @task_enabled_guard decorator on every task provides secondary safety check
  5. Logging: TaskLogger logs execution to BkLog model with category, duration, success/failure

🔧 Celery Beat Scheduler

Uses a custom DBReloadScheduler (subclass of PersistentScheduler) that loads the schedule from the database on startup.

# CRITICAL: Always use the custom scheduler python -m celery -A mcube_ai beat \ --scheduler=mcube_ai.celery:DBReloadScheduler \ --loglevel=info # Or use the helper function (recommended) from apps.core.views import ensure_celery_running ensure_celery_running() # Starts worker + restarts beat

Warning: Never run two beat processes simultaneously — tasks will execute twice (duplicate Telegram messages, duplicate trades).
